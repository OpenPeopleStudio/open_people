# PLAN — `/ask` QR Q&A (22 Oct 2026)

## Goal

A public Q&A page at **openpeople.ai/ask**, reached by QR code, where anyone can ask about Open People’s **preliminary proposal**. Answers come from a knowledge file, are labelled honestly, and unanswered questions go to Tom by email.

## In (this slice)

- `/ask` in the existing desk style (void field, plasma `#e8893c`).
- Plain intro: *Ask anything about Open People's preliminary proposal. Answers are honest and labelled. If we don't know yet, we'll find out and email you.*
- Chat UI → server route → Vercel AI SDK via AI Gateway. Answers **only** from `content/ask/proposal-knowledge.md`.
- Labels: **CONFIRMED / REPORTED / ESTIMATE / UNKNOWN**. Never invent numbers. Never claim partners or tenants have agreed. Never speak about snōw white laundry or personal matters. Transparent that this is an AI assistant for Open People.
- If not covered: say so and offer the follow-up form (name optional, email required, question).
- Follow-up emails `tom@openpeople.ai` via Resend if `RESEND_API_KEY` is set; otherwise store on a server-side log and document the env vars.
- Log every question (text + covered yes/no). **No emails in the public question log.**
- Basic rate limit + honeypot. Privacy line: what is collected and why.
- No auth. No analytics trackers. Placeholder knowledge file for Tom’s team to paste the proposal.

## Out

- Filling the proposal text (Tom’s team drops it into the knowledge file).
- Auth, accounts, or a logged-in desk.
- Analytics / pixels / session replay.
- Dollar figures, capex, or named customers invented by us.
- Phone numbers, street addresses, SWL, Brendan.
- Changes to `/letter`.
- Merge to `main` or production. Tom says “ship it” first.

## Dest

- This repo. Vercel project `open-people`. Public URL: `https://www.openpeople.ai/ask`.
- Ship path: feature branch → PR → Vercel preview. QR points at `/ask` after Tom ships.

## First slice (this PR)

Ship a working `/ask`: page + chat + knowledge-bound system prompt + follow-up form + logs + spam guards + OG. Knowledge file is a **placeholder header** only.

## Later slices (not this PR)

- Tom’s team replaces `content/ask/proposal-knowledge.md` with the proposal.
- Optional: persist question logs to a table; QR landing analytics without trackers (server counts only).
- Optional: nav placement if `/ask` should sit next to Vision.

## Done when

- `/ask` renders the locked intro, chat, follow-up form, and privacy line on a Vercel preview.
- Chat refuses to answer outside the knowledge file and labels UNKNOWN when the file is still a placeholder.
- Follow-up posts to `tom@openpeople.ai` when Resend is configured; otherwise a server log entry (no email addresses in the public question log).
- Rate limit + honeypot in place. No new auth. `/letter` unchanged.
- Env vars Tom must set are listed below and in the PR.

## Env vars Tom must set

| Variable | Required? | Purpose |
| --- | --- | --- |
| `AI_GATEWAY_API_KEY` | Local / non-Vercel. On Vercel, OIDC (`VERCEL_OIDC_TOKEN`) is enough if the project is linked. | Authenticate AI Gateway. |
| `AI_GATEWAY_MODEL` | Optional. Default `openai/gpt-4.1-mini` (live Gateway id). | Chat model, `provider/model` form. |
| `RESEND_API_KEY` | To actually email Tom. Already used by this app. | Send follow-ups. |
| `ASK_FROM_EMAIL` | Optional. Default `Open People <tom@openpeople.ai>`. | Verified Resend From. Change if Resend rejects the default. |
| `ASK_TO_EMAIL` | Optional. Default `tom@openpeople.ai`. | Follow-up inbox. |
| `ASK_LOG_PATH` | Optional. | JSONL file for question + undelivered follow-up logs (in addition to server logs). Useful locally. On Vercel, structured logs are the store unless this path is a writable volume. |

Never commit secrets. Preview and production: Vercel project **open-people** → Settings → Environment Variables.
